## 一、arXiv最新AI论文（2026.11.01-11.03）

### 1. Routed Continual Learning：让 Agent 系统复用历史经验、API 成本降 72%

**摘要**：Meta FAIR 提出"路由式持续学习"（Routed CL），将历史轨迹归入不同簇并各自维护记忆；每次运行前由 LLM 路由器判断当前任务与哪类经验最接近，决定复用某簇或新建。评测覆盖 6 个 CL-Bench 任务 301 个实例与 τ³-Bench 97 个银行对话实例。

**领域**：Agent 持续学习 / 记忆系统

**推荐理由**：直击多 Agent 长期运行时的"经验干扰 vs 上下文膨胀"两难——不是粗暴保留全部历史，而是按任务语义路由到合适的记忆簇，实测将 API 成本压低 72%，对生产级 Agent 落地有直接的工程价值。

**链接**：https://arxiv.org/abs/2610.38796

### 2. SWE-Shift：在"中途变卦"的仓库里考验编程 Agent

**摘要**：现有仓库级编程基准假设任务与环境不变，而真实开发中代码、依赖、运行时状态与需求都会在 Agent 工作时变化。SWE-Shift 从同一份历史与 workspace 构造"Clean 续作"与"Shifted 续作"，含 12 个变更族 120 个场景、每个 9 个干预点；评测 17 个编程 Agent 系统，Shifted 成功率全面低于 Clean（GPT-6 Astra 从 67.35% 跌到 24.79%）。

**领域**：代码智能 / Agent 评测

**推荐理由**：把"中途插入需求变更"这一真实痛点做成了可量化基准，暴露了所有系统"能完成原任务却保不住已有工作、刷不新证据"的共性短板，比 SWE-bench 更贴近真实协作。

**链接**：https://arxiv.org/abs/2610.32196

### 3. FeatureLoop：用"需求会演化"的视角给编程 Agent 打分

**摘要**：FeatureLoop 是 61 个人工审阅任务（34 个仓库、5 种语言、7 种软件形态）的基准，每个任务在持久 workspace 中经历"演化反馈"（追加/澄清需求）与"完成反馈"（报告失败）。累计可执行检查跟踪新行为、修复与旧功能保留；评测 12 个前沿模型，最强者双反馈任务完成率 72.1%，但失败阶段仅 15.4% 能在两次修订内恢复。

**领域**：代码智能 / Agent 评测

**推荐理由**：与 SWE-Shift 形成互补——它聚焦"用户先粗略提需求、试用后再细化"的迭代式开发，量化了"重复指导成本"，揭示修复不完整、回归与模型特定反馈利用差异等可靠低干预开发的障碍。

**链接**：https://arxiv.org/abs/2610.35488

### 4. TPAE：无需辅助奖励模型的多模态推理强化

**摘要**：针对多模态 RLVR 仅有序列级奖励、缺乏对视觉基础步骤细粒度监督的问题，SMU 提出 Token-Level Perception-grounded Advantage Estimation（TPAE）。它用 token 级"视觉依赖性"与"预测熵"的统计对齐来细化优势信号，无需训练额外奖励模型，可无缝接入 GRPO/DAPO；在 7 个多模态基准上稳定优于强基线。

**领域**：多模态推理 / 强化学习

**推荐理由**：用一个模型内禀指标替代昂贵的 process reward model，既降低算力又规避奖励黑客——并且点出了"non-resolving grounding"这一关键失败模式（盯着图却没提取出信息），对做多模态 RL 的团队是直接可用的训练技巧。

**链接**：https://arxiv.org/abs/2609.39168

### 5. PixelUMM：丢掉 VAE 与 ViT 的像素空间统一多模态模型

**摘要**：NVIDIA 与滑铁卢大学提出 PixelUMM，直接在像素空间统一图像与视频的理解与生成：图像切成空间 patch、视频切成时空 tubelet，仅用一层线性投影接入共享多模态主干（Mixture-of-Transformers，理解与生成各有参数但共享注意力）。已开源代码、模型与项目主页。

**领域**：统一多模态模型 / 视觉生成

**推荐理由**：把"无编码器"的像素空间范式从图像扩展到视频，省掉 VAE/ViT 双流接口、缩短视觉上下文，且能直接复用成熟 VLM 预训练流程——为统一理解与生成的架构选择提供了一条更简洁的路线。

**链接**：https://arxiv.org/abs/2609.38597

### 6. DriftTTS：一步到位的单步语音合成

**摘要**：基于 score/flow matching 的 TTS 需多次调用解码器导致慢；现有加速要么蒸馏多步教师、要么在预训练模型上加 stage。KAIST 等提出 DriftTTS，用 generative drifting 把迭代采样从推理搬进训练（并以 segment drifting 处理语音变长），在 LJSpeech 上单解码调用即匹配 Matcha-TTS / RapFlow-TTS 的多步质量且更快，据称是 generative drifting 首次用于 TTS。

**领域**：语音合成 / 生成模型

**推荐理由**：挑战了"单步 TTS 必须先预训练一个 TTS 模型"的默认假设，给出一条不依赖教师蒸馏的极简加速路径，对端侧/实时语音场景有实用意义。

**链接**：https://arxiv.org/abs/2610.22960

### 7. 后训练前先量潜力：从基座模型预测编码 Agent 表现

**摘要**：NVIDIA 联合明尼苏达大学、UC Berkeley 提出新评测法（arXiv:2610.10478）：不要求基座模型冷启动跑完整 Agent 流程，而是重播一条成功解题轨迹、找出"让测试由败转胜"的决定性步骤，在那一关键点评估基座模型的后训练潜力。10 组模型排序与 SWE-bench Verified 后训练成绩相近；而直接跑全流程的 6 个基座里有 5 个零分。

**推荐理由**：在砸下大笔后训练算力之前给出一个低成本的"值不值得训"排序信号，直击企业选型痛点——避免把后训练预算浪费在潜力不足的 checkpoint 上。

**链接**：https://arxiv.org/abs/2610.10478

### 8. 多 Agent 系统的"同质化"失灵模式

**摘要**：NVIDIA 等通过一致性（向多数靠拢）、极化（向极端偏移）与惯性（抗拒改变）三指标，将多 Agent 系统的同质化操作化并量化。在代码生成、招聘、科研同行评审三任务中，同质化带来具体下游风险：代码生成中隐藏并放大相关性错误、招聘中让偏见 Agent 的影响在移除后仍长期存续、同行评审中造成跨领域评价标准不一。简单提升多样性（采样随机性、混用模型）均未能降低风险。

**领域**：多 Agent 系统 / 可信 AI

**推荐理由**：提醒业界"多 Agent 协作"并非越多越好——交互本身会收敛出相似行为、放大共性失败，且常规多样性手段无效，倒逼评测从聚合性能转向交互动力学分析。

**链接**：https://arxiv.org/abs/2610.09824
